RQ1ConvertToRimay

The experiment. Takes a CSV exported from the annotation tool, asks an LLM to convert NL → Rimay, scores it. No database.

gold CSV→ Stage 1 convert → llm_rimay/→ Stage 2 score → results.json→ Stage 3 verdict → report.html
DATA inputs CALC where numbers are computed OUT results

Inputs — data/

FileWhat
gold_annotations_main.csvAll 50 main requirements, straight from the tool's export. 151 rows.
gold_annotations_main_atomic.csvThe 30. The above minus non-atomic, minus drafts. 90 rows. This is what runs.
gold_annotations_main_atomic_excluded.txtThe 20 excluded, with which annotator gave which signal.
refinements.json90 hand edits to the annotators' conversions (scope, typos, wording). Edit this to redo.
gold_annotations_main_atomic_refined.csvThe 30, refined. Same 31 columns as the original; rimayText, slot_scope, gold_scope overwritten.
…_refined_review.htmlEvery edit as a word diff. Open this to check the changes.
gold_annotations.csvOld pilot export. Superseded.
Pipeline: tool export → make_atomic_gold.py (the 30) → apply_refinements.py (refined text) → run with --gold data/gold_annotations_main_atomic_refined.csv.

How the 30 were made: export all of main from the tool → scripts/make_atomic_gold.py drops drafts, then drops any requirement where any annotator signalled non-atomic by checkbox, <NON_ATOMIC> tag, or notes. 50 → 20 excluded → 30 kept. Re-runnable: re-export, re-run.

Number in the reportComputed in

The written verdict paragraphsverdict.py
Re-scoring wipes verdicts. run_scoring.py rewrites results.json, and the per-run verdict lives inside it. After any re-score, re-run scripts/run_verdict.py --batch <run>. The batch verdict.md is a separate file and survives.
